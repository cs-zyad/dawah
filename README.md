## التشغيل المحلي

**المتطلبات:** Node.js 20+ و Java 11+ (لمحاكي Firestore الرسمي). على ماك: `brew install openjdk@21`.

```bash
npm install
npm run dev:local
```

هذا الأمر بلا أي حساب Firebase:
- يشغّل محاكي Firestore الرسمي مع **حفظ البيانات بين التشغيلات** (في `.emulator-data/`).
- يعبّئ البيانات التجريبية مرة واحدة (أول تشغيل فقط) ويطبع روابط التجربة.
- يشغّل المنصة على `http://localhost:3000` مع عامل المهام داخل الخادم (كل 15 ثانية).

للتجربة من الجوال على نفس الشبكة: `npm run dev:local -- --lan` (الكاميرا تحتاج HTTPS؛ استخدم البدائل اليدوية أو Codespaces).

### من الجوال عبر GitHub Codespaces

افتح المستودع في Codespaces (Code → Codespaces → Create). الإعداد في `.devcontainer/` يثبّت Java ويشغّل كل شيء تلقائيًا، ويضبط `APP_URL` على رابط المنفذ 3000 (HTTPS، فتعمل الكاميرا). لمشاركة روابط الدعوات مع ضيوف من أجهزة أخرى اجعل المنفذ 3000 **Public** من تبويب Ports.

### أوامر أخرى

| الأمر | الوظيفة |
|---|---|
| `npm test` | الاختبارات الآلية على محاكي Firestore (لا تمس قاعدة حقيقية) |
| `npm run test:e2e` | اختبار الرحلة كاملة في متصفح حقيقي (بناء إنتاجي + كاميرا افتراضية؛ يحتاج ffmpeg) |
| `npm run seed` | تعبئة البيانات التجريبية (لا تكرر إن شُغّلت مرتين) |
| `npm run worker` | عامل المهام مستقلًا (بديل لعامل الخادم) |
| `npm run typecheck` / `npm run lint` | فحص الأنواع والكود |

## الإعداد على Firebase + Vercel

### 1. مشروع Firebase وقاعدة Firestore
1. افتح [console.firebase.google.com](https://console.firebase.google.com) ← **Add project** (لا حاجة لـ Google Analytics).
2. من القائمة: **Build → Firestore Database → Create database**.
3. اختر **Production mode** (القواعد تمنع أي وصول من المتصفحات، وهذا المطلوب).
4. الموقع: **`europe-west3` (Frankfurt)** — لا يمكن تغييره لاحقًا. (انظر القرار المفتوح عن PDPL.)
5. انشر قواعد الأمان من المستودع (اختياري، الافتراضي في Production mode مكافئ):
   ```bash
   npx firebase deploy --only firestore:rules --project <PROJECT_ID>
   ```
   القواعد في [`firestore.rules`](firestore.rules): `allow read, write: if false` — كل الوصول من الخادم فقط عبر `firebase-admin`.

### 2. مفتاح حساب الخدمة
1. **Project settings (⚙) → Service accounts → Generate new private key** ← يُنزَّل ملف JSON.
2. ⚠ **الملف سرّي**: لا تضعه داخل المستودع ولا ترفعه على GitHub (أنماطه مضافة إلى `.gitignore`).
3. انسخ محتوى الملف كاملًا (أو حوّله إلى base64: `base64 -i key.json | tr -d '\n'`).

### 3. Vercel
1. [vercel.com/new](https://vercel.com/new) ← استورد المستودع `dawah`. الإطار يُكتشف تلقائيًا (Next.js).
2. **Settings → Environment Variables** وأضف:

   | المتغير | القيمة |
   |---|---|
   | `FIREBASE_SERVICE_ACCOUNT` | محتوى ملف JSON كاملًا (أو base64) |
   | `DEMO_MODE` | `true` للتجربة (يعبّئ البيانات التجريبية ويفعّل الصفحتين التجريبيتين) — `false` للإنتاج الحقيقي |
   | `PAYMENT_WEBHOOK_SECRET` | سلسلة عشوائية طويلة: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
   | `CRON_SECRET` | سلسلة عشوائية طويلة (Vercel يرسلها مع المهمة المجدولة) |
   | `APP_URL` | اختياري؛ يُستنتج من `VERCEL_PROJECT_PRODUCTION_URL` |

3. **Deployments → Redeploy** بعد إضافة المتغيرات. أمر البناء (`npm run build`) يتحقق أولًا من ضبط Firebase ويطبع رسالة عربية واضحة إن لم يُضبط، ثم يعبّئ البيانات التجريبية مرة واحدة إن كان `DEMO_MODE=true`.
4. المنطقة مضبوطة في [`vercel.json`](vercel.json): `"regions": ["fra1"]` لتكون الدوال بجانب قاعدة البيانات في فرانكفورت.
5. المهمة المجدولة `/api/cron` مضبوطة يوميًا (الخطة المجانية تسمح بمرة يوميًا فقط). انظر القرار المفتوح رقم 6.

> قائمة المتغيرات موثّقة في [`.env.example`](.env.example).

## حسابات التجربة

كلمة المرور لكل الحسابات: **`Wafda@2026`**

| الحساب | البريد | الغرض |
|---|---|---|
| منظّم | `organizer@wafda.test` | 4 فعاليات ورصيد 100 ر.س |
| فريق استقبال | `staff@wafda.test` | معيّن على فعاليتين (1 و2) |
| أدمن | `admin@wafda.test` | لوحة الأدمن `/admin` |
| منظّم آخر | `other@wafda.test` | اختبار عزل البيانات |
| استقبال فعالية أخرى | `staff2@wafda.test` | اختبار تقييد الصلاحيات |

**الفعاليات التجريبية:**
1. «ملتقى النادي السنوي» — دعوات خاصة مدفوعة بسياسة انتظار: دعوة فردية لم ترد، ودعوة بمرافق لم ترد، ومؤكدة منفردة، ومؤكد مع مرافق حضر ضيفه ولم يحضر مرافقه، ومعتذرة، ورقم يفشل إرساله، ومدعوة بالبريد فقط، ومدعوان لم تُرسل دعوتهما.
2. «ورشة تصميم واجهات المستخدم» — رابط عام مدفوع بقائمة انتظار، فيه مسجلون أحدهم حضر.
3. «جلسة حوارية» — رابط عام مكتمل العدد بسياسة إغلاق.
4. «حفل تخرج الدفعة» — مسودة.
5. «اجتماع الشركاء الربعي» — لمنظّم آخر.

ومعها: طلب تصميم بانتظار المراجعة، وطلب وصله عرض سعر، وشكوى مفتوحة. سكربت التعبئة يطبع روابط التجربة الجاهزة (الدعوات، التذاكر، الروابط العامة).

## رحلة تجربة في 10 دقائق

1. **المنظّم** — ادخل بـ `organizer@wafda.test` ← «+ فعالية جديدة» ← عبّئ البيانات واختر «خاصة بالاسم».
2. **القالب والمعاينة** — اختر قالبًا، وشاهد صفحة الدعوة ونص واتساب والبريد ورسالة التأكيد (كلها من مصدر واحد).
3. **المدعوون** — أضف مدعوًا برقمك المحلي مع «يسمح بمرافق»، وآخر ببريد. أو نزّل الملف النموذجي واستورده (معاينة: مقبول / مكرر / يحتاج تصحيحًا).
4. **الدفع** — «الباقة والدفع» ← الملخص (مثال: 40 دعوة منها 10 بمرافق = 50 مكانًا) ← «ادفع» ← صفحة الدفع التجريبية ← «ادفع الآن». جرّب «إعادة إرسال نفس الإشعار»: لا يتكرر الأثر.
5. **الإرسال** — «الإرسال والتذكيرات»: التكلفة المتوقعة لكل قناة، ثم «إرسال الدعوات». الرصيد يُخصم.
6. **الضيف** — افتح `/dev/inbox` (من الجوال أفضل) ← اضغط رابط الدعوة ← «معي مرافق» ← «أكّد حضورك» ← تذكرتان مستقلتان؛ تذكرة المرافق فيها زر مشاركة.
7. **الاستقبال** — من جوال آخر ادخل بـ `staff@wafda.test` أو بحساب المنظّم ← «التحضير» ← الفعالية ← «تشغيل الكاميرا» ← امسح التذكرة: «تم تسجيل الدخول». امسحها مجددًا: «حضر مسبقًا» مع الوقت والطريقة.
8. **تعذّر عرض الرمز** — ابحث باسم المدعو أو جزء من جواله ← «تسجيل الحضور يدويًا» للمرافق.
9. **اللوحة** — «نظرة عامة»: الدعوات، لم يؤكد، المؤكدون (أشخاص + دعوات)، الحاضرون (ضيوف + مرافقون)، المتاح، تعذّر الإرسال، الانتظار، اعتذر، وآخر من حضر. نزّل «كشف الحضور CSV».
10. **العزل والصلاحيات** — ادخل بـ `staff2@wafda.test` وافتح رابط تحضير الفعالية: «غير موجودة». ادخل بـ `admin@wafda.test` وتصفّح لوحة الأدمن (المدفوعات، الإشعارات، الرسائل والتكلفة، سجل التدقيق، الأسعار والسياسات).

## محاكاة الحالات

في الوضع التجريبي (`DEMO_MODE=true`):

| الحالة | كيف |
|---|---|
| فشل نهائي للرسالة (تُسترجع قيمتها) | رقم ينتهي بـ `0000` أو بريد يحتوي `fail` |
| فشل مؤقت ثم نجاح (إعادة محاولة) | رقم ينتهي بـ `1111` أو بريد يحتوي `flaky` |
| فشل الدفع | زر «محاكاة فشل الدفع» في `/dev/checkout/[id]` |
| إشعار دفع مكرر | زر «إعادة إرسال نفس الإشعار» |
| رصيد غير كافٍ | أرسل لعدد يتجاوز الرصيد؛ وغيّر السياسة من `/admin/settings` |
| اكتمال العدد / قائمة الانتظار | قلّل «الحد الأقصى للحضور» من تبويب البيانات |
| فرض قارئ jsQR بدل BarcodeDetector | افتح `/checkin/<id>?engine=jsqr` |

صندوق الرسائل التجريبي: `/dev/inbox` — رسائل واتساب والبريد بروابط قابلة للنقر، مع تصفية بالمستلم.

## القرارات المهمة

- **السعة الفعلية = الأقل بين الحد الأقصى والأماكن المدفوعة** (للنوعين). الحجز والسعة يُحسمان داخل `runTransaction` يقرأ وثيقة الفعالية ثم يكتب (كل القراءات قبل الكتابات). اختبار: 20 تسجيلًا متزامنًا على 5 مقاعد = 5 بالضبط، و56 على 50 مكانًا مدفوعًا = 50.
- **القيود الفريدة بمعرّفات وثائق ثابتة:** تسجيل الدعوة `inv_<invitationId>`، التذكرة `<registrationId>_<kind>`، عضو الفريق `<eventId>_<userId>`، قيد الرصيد = بصمة مفتاح منع التكرار، التسجيل العام = بصمة (الفعالية + مفتاح النموذج)، ووسيلة التواصل داخل الفعالية في مجموعة `uniques`.
- **الاستعلامات بفلاتر مساواة فقط والترتيب في الذاكرة** — لا فهارس مركّبة (المحاكي لا يفرضها).
- **نسخة حالة التأكيد على الدعوة** (`regStatus`) تُحدَّث في نفس المعاملة لتسهيل استعلام «لم يرد».
- **فصل الأماكن المدفوعة عن المقاعد المحجوزة:** الدعوة بمرافق = مكانان في الباقة، لكن مقعد المرافق يُحجز فقط إذا أضافه الضيف عند التأكيد.
- **دفعة الرسائل:** الخصم + عناصر الدفعة في نفس المعاملة، ثم إنشاء الرسائل بمعرّفات ثابتة `<batchId>_<i>`، والعامل يكمل الدفعات المعلّقة. نفس الضغطة لا تخصم مرتين.
- **الرسائل:** 3 محاولات بمهلة متضاعفة للفشل المؤقت، ثم «فشلت» مع استرجاع تلقائي (قيد استرجاع بمعرّف ثابت). حجز الرسالة بـ lease يمنع عاملين من إرسالها معًا.
- **الدفع يُثبَّت فقط عبر الإشعار الموقّع** (توقيع + مبلغ + عملة)، ويسجَّل كل إشعار بمعرّفه ويطبَّق أثره مرة واحدة داخل معاملة. صفحة العودة لا تثبت شيئًا.
- **رمز QR = رابط التذكرة فقط** (رمز عشوائي 160 بت بلا بيانات شخصية). المسح والتحضير اليدوي مسار واحد في معاملة، حتى مع مسحين متزامنين.
- **التذكرة لفعالية أخرى** تعطي «لا تخص هذه الفعالية» دون أي بيانات.
- **عزل المنظّمين:** كل عملية تتحقق من المالك في الخادم؛ فعالية منظّم آخر = 404.
- **الأمان:** scrypt لكلمات المرور، جلسة برمز عشوائي تُخزَّن بصمته فقط في كوكي HttpOnly + SameSite=Lax، فحص Origin وSec-Fetch-Site فوق حماية Next المدمجة، حد للمحاولات على الدخول والتسجيل والتسجيل العام، إيقاف الحساب ينهي جلساته، وسجل تدقيق للدفع والإعدادات والصلاحيات والإلغاء والتسويات.

### حدود معروفة
- **وثيقة الفعالية «ساخنة»:** كل حجز يكتب عداد المقاعد على نفس الوثيقة. Firestore يتحمّل نحو كتابة واحدة في الثانية بثبات على الوثيقة الواحدة مع دفعات قصيرة أعلى؛ المعاملات تعيد المحاولة حتى 40 مرة. يكفي لتسجيلات فعالية بمئات الأشخاص. للفعاليات الضخمة بموجات تسجيل لحظية بالآلاف يلزم تقسيم العداد (sharded counters) أو طابور.
- لوحة الأدمن تقرأ المجموعات كاملة لحساب المؤشرات — مناسب للتجربة، ويحتاج تجميعًا دوريًا عند النمو.
- عامل المهام داخل خادم Next لا يعمل على Vercel؛ هناك الإرسال الفوري يتم مع كل إجراء، والتذكيرات المجدولة وإعادة المحاولة عبر `/api/cron`.

## حالة كل ربط

| الخدمة | الحالة | الملاحظات |
|---|---|---|
| قاعدة البيانات (Firestore) | **فعلي** | عبر حساب خدمة، أو المحاكي الرسمي محليًا |
| واتساب | **تجريبي (mock)** | `MessageProvider` في `src/lib/providers/messaging.ts`؛ النصوص قوالب بمتغيرات جاهزة للاعتماد |
| البريد | **تجريبي (mock)** | نفس الواجهة |
| الدفع | **تجريبي (mock)** | `PaymentProvider` في `src/lib/providers/payments.ts`؛ المعالجة الفعلية (التوقيع، المبلغ، العملة، عدم التكرار) حقيقية ومختبَرة |
| المهام المجدولة | **فعلي** | instrumentation محليًا، `npm run worker`، أو Vercel Cron |

حالة الربط تظهر أيضًا في `/admin`.

## الافتراضات

- نوع الدعوة لكل فعالية واحد: خاصة أو عامة، ولا يتغير بعد الدفع.
- الضيف بلا حساب ولا رمز تحقق في النسخة الأولى.
- رسالة التأكيد تحمل رابط صفحة التذكرة (QR يظهر في الصفحة)؛ إرفاق صورة QR يأتي مع اختيار المزوّد.
- رسالة فرصة الانتظار تُخصم من رصيد الرسائل.
- العرض بتوقيت الرياض وتقويم ميلادي وأرقام لاتينية.
- **إعادة إرسال التذكرة** (من المنظّم أو تلقائيًا عند إدخال وسيلة مسجلة) تُعامل كرسالة تأكيد: مشمولة في الباقة بتكلفة تشغيل تقديرية، مع حد أدنى للمدة بين كل إعادة (افتراضيًا 10 دقائق).
- **دعوة عضو الاستقبال** على حساب المنصة (لا تُخصم من رصيد المنظّم).
- **الرابط العام بلا مرافقين**: التسجيل العام مقعد واحد لكل شخص.
- السعة الفعلية في الدعوات الخاصة أيضًا = الأقل بين الحد الأقصى والأماكن المدفوعة، فيمكن دعوة أكثر من الحد مع سياسة انتظار.
- المدعو الذي **ألغى المنظّم** تسجيله لا يستطيع التأكيد مجددًا من رابطه (بخلاف المعتذر).
- **قائمة الانتظار لا تُتجاوز تلقائيًا**: المنظّم يختار من يرسل له الفرصة، ويمكن إرسال أكثر من فرصة لمقعد واحد ويفوز من يؤكد أولًا.
- لا يمكن الاعتذار أو إلغاء التسجيل بعد تحضير أي تذكرة من التسجيل.
- لم تُرفق ملفات الهوية الرسمية بعد؛ الشعار والقوالب مؤقتة ومبنية من الألوان المحددة.
- الأسعار تجريبية مُعلّمة: باقات 50/100/250/500/1000 مكان بـ 99/179/399/699/1199 ر.س، المكان الإضافي 2 ر.س، واتساب 0.25 ر.س، بريد 0.05 ر.س — كلها قابلة للتعديل من `/admin/settings`.

7. **ملفات الهوية الرسمية** (Brand Guide وBrand Kit) لاستبدال الشعار والقوالب المؤقتة.
8. **الإطلاق الأول:** تجربة على ورشة أو فعالية حقيقية واحدة لقياس وقت تجهيز الدعوات، وسرعة الدخول، ودقة كشف الحضور، واستعداد المنظّم للدفع، وتكلفة رسائل التأكيد، قبل اعتماد الأسعار.
